# Phase 2 — UI Design Contract

> Visual and interaction contract for Phase 2 (Case Scenario & Core Document). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform:** WinForms desktop (net10.0-windows). Everything is built in code (`InitializeUI()`, `TableLayoutPanel` root docked `Fill`, row-index comments). All pixel values are logical pixels at 96 DPI. The form uses `AutoScaleMode.Font`, so values scale with DPI. Font sizes are in **points (pt)**, the WinForms unit.
>
> **Mode:** Written with `--auto`. There is no CONTEXT.md and no user Q&A. Every choice below comes from 02-RESEARCH.md, CLAUDE.md, or the existing controls (`Helpers/ButtonHelper.cs`, `Forms/WizardForm.cs`, `UserControls/StepTopicInput.cs`, `StepStorylines.cs`, `StepApiConfiguration.cs`, `StepGeneration.cs`, `Helpers/LoadingOverlay.cs`). Any choice not taken from those sources is marked **[DEFAULT]** and listed in the Assumptions table at the end.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (WinForms. shadcn does not apply) |
| Preset | not applicable |
| Component library | Standard WinForms controls plus the in-repo helpers `Helpers/ButtonHelper` (`CreateButton`, `ButtonStyle`) and `Helpers/LoadingOverlay` |
| Icon library | none. The UI is text only: no icons, glyphs or emoji. Status is shown with text suffixes and ForeColor |

Shell (existing, unchanged): `WizardForm` 900x600 client size (minimum 800x500). It has a dark header band (45,45,48) with the step title at 14pt Bold white, a content panel with padding (15,10,15,10), and a bottom nav bar 60px high with Cancel / < Back / Next > buttons at 100x35.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between a label and its hint text. FlowLayoutPanel control margin (`Margin = new Padding(0, 4, 4, 0)`) |
| sm | 8px | Root `TableLayoutPanel.Padding` for new steps and dialogs. Gap between adjacent buttons. `SplitContainer.SplitterWidth` |
| md | 16px | Right margin between groups in a horizontal FlowLayoutPanel (radio buttons, combos). Inner padding of the warning banner |
| lg | 24px | Height of hint and counter rows. Owner-drawn ListBox `ItemHeight` |
| xl | 32px | Height of in-step buttons (`CreateButton(..., 32, ...)`). Height of input and combo rows |
| 2xl | 48px | Height of the dialog footer button bar. Height of the preset summary row (two text lines) |

Spacing tokens (padding, margins, gaps) use only the values in the table. TableLayoutPanel row heights, column widths, grid column widths and fixed control sizes (for example rows of 28, 40 and 112, grid columns of 80, 128, 136 and 180, and the 240 splitter distance) are **component dimensions, not spacing tokens**. They must still be multiples of 4. New row heights use 24, 28, 32, 40, 48, 64, 112, or `SizeType.Percent`.

Exceptions:
- Step UserControl `this.Padding = new Padding(20)` preserves the existing convention used by all legacy steps (`StepTopicInput`, `StepStorylines`). Changing it would misalign new steps with the rest of the wizard.
- The existing shell nav buttons (100x35) and the existing `mainLayout.Padding = 10` in legacy steps stay as they are. They are not re-specified here.
- `ButtonHelper.CreateButton` adds 24px of internal text padding and auto-widens. The widths below are minimums.
- 28px is allowed for single-line bold label rows (matches `StepApiConfiguration` header rows).

## Typography

WinForms line height comes from the font metrics (Segoe UI is about 1.33x) and cannot be set per control. The "Line Height" column shows the effective value. Multiline `TextBox` controls get no extra leading.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 9pt | Regular | ~1.33 (font metric) | Hint text, status labels, preset summary, grid and list cells, radio and checkbox text, MessageBox copy (system font) |
| Label | 9pt | Bold | ~1.33 | Field captions ("Describe the dispute or investigation"), grid column headers, issues-panel caption |
| Editor | 10pt | Regular | ~1.33 | Scenario TextBox, section editor TextBox, full preview TextBox, guidance TextBox, combos |
| Heading | 12pt | Bold | ~1.33 | Document title in `StepCoreDocument` (for example "Complaint — U.S. District Court, N.D. Illinois"), selected section heading above the editor, dialog headline in the warning banner |

Only two weights are used: **Regular (400)** and **Bold (700)**. Italic is not used in new UI.

Construct fonts as `new Font("Segoe UI", 10F)` and `new Font("Segoe UI", 12F, FontStyle.Bold)`, or as `new Font(this.Font, FontStyle.Bold)` for 9pt labels (the existing pattern). The existing 14pt Bold shell header and the 18pt Bold `LoadingOverlay` message are inherited display roles and are not redefined.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `SystemColors.Control` (240,240,240) | Step and dialog backgrounds (default UserControl/Form BackColor, not set explicitly) |
| Secondary (30%) | `SystemColors.Window` (255,255,255) | Input and reading surfaces: scenario TextBox, section editor, preview TextBox, section ListBox, entity grid (`BackgroundColor = SystemColors.Window`), issues grid |
| Accent (10%) | `Color.FromArgb(0, 120, 215)` (ButtonStyle.Primary blue) | See the reserved list below |
| Destructive | `Color.FromArgb(220, 53, 69)` (ButtonStyle.Danger) | Only the **Cancel Generation** button in `StepCoreDocument` |

Accent is reserved for:
1. **One** Primary button per surface: `Generate Document` (empty state) or `Regenerate Section` (editor toolbar) in `StepCoreDocument`, `Apply Substitutes` in `EntityReviewDialog`, and the existing shell `Next >`.
2. The selected-item background in the owner-drawn section ListBox, with white text.
3. In-progress status text ("Writing Count II of IV...", "Checking the scenario for real names...").

Accent is not used for links, headings, borders or secondary buttons. All other buttons use `ButtonStyle.Default`.

Semantic text colors (reuse the existing values. Do not add new ones):

| Meaning | Value | Where |
|---------|-------|-------|
| Error | `Color.Red` | Error status label, Error rows in the issues grid, "Failed" section items |
| Warning | `Color.DarkOrange` | Warning rows, sections with warnings, "out of date" notice, scenario counter over 90% of the cap |
| Success | `Color.Green` | "No issues found" and "Document ready" status |
| Muted | `Color.DimGray` | Hints, character counter, "pending" section items |

Warning banner in `EntityReviewDialog` (the only new colors in this phase): background `Color.FromArgb(255, 243, 205)`, text `Color.FromArgb(133, 100, 4)`, 1px border `Color.FromArgb(255, 222, 120)` drawn with `BorderStyle.FixedSingle` on the panel.

## Screen Contracts

### S0. Flow selector (small addition to `StepApiConfiguration`)

- Add rows at the **bottom** of the existing `mainLayout`: a 28px row with the 9pt Bold label `Workflow`, then a 32px row with a FlowLayoutPanel holding two RadioButtons (16px right margin between them):
  - `Case-driven (new)`, checked by default [DEFAULT, research A2]
  - `Legacy topic wizard`
- Keep the row-index comments in sync. Changing the radio sets `WizardState.Flow`. `WizardForm` rebuilds the step list when leaving step 0, and the header shows "Step X of N" from the new list.

### S1. `StepCaseScenario` (step title: `Describe the Case`)

`this.Padding = new Padding(20)`. Root `TableLayoutPanel`, 1 column, `Padding = new Padding(8)`:

| Row | SizeType | Content |
|-----|----------|---------|
| 0 | Absolute 28 | Label (9pt Bold): `Describe the dispute or investigation` |
| 1 | Percent 100 | Scenario TextBox: `Multiline`, `ScrollBars.Vertical`, `WordWrap`, `AcceptsReturn`, 10pt, `MaxLength = 0` (the cap is enforced in validation, so pastes are never truncated silently), `Dock = Fill` |
| 2 | Absolute 24 | TableLayoutPanel with 2 columns: left hint (9pt DimGray) `Name the parties, what went wrong, and roughly when. Real names will be checked and replaced.` Right, right-aligned counter `{n:N0} / 8,000 characters` (DimGray, DarkOrange above 7,200, Red above 8,000) |
| 3 | Absolute 28 | Label (9pt Bold): `Complexity` |
| 4 | Absolute 32 | FlowLayoutPanel of RadioButtons: `Simple`, `Standard` (default checked), `Complex`, with 16px right margin |
| 5 | Absolute 48 | Preset summary Label (9pt Regular, default ForeColor, `AutoSize = false`, `Dock = Fill`). Updates immediately on radio change |
| 6 | Absolute 28 | Label (9pt Bold): `Document and court (optional)` |
| 7 | Absolute 32 | FlowLayoutPanel: caption `Document:` + ComboBox (DropDownList, width 180) `Auto-detect`, `Complaint`, `Petition`, `Investigation Memo`. Caption `Court:` + ComboBox (width 120) `Auto`, `Federal`, `State`. Caption `State:` + ComboBox (width 160) `Auto` + 50 states + `District of Columbia` (enabled only when Court = State). Each group has a 16px right margin |
| 8 | Absolute 24 | Status label (9pt). Accent while detecting, Red on error, Green on "No real names found." |

Preset summary format (one line per preset, values from `ComplexityPreset.Get(level)`, never hardcoded in UI):
- `Simple: 2 parties · 1-2 counts or issues · 6-10 key characters · 3-6 month timeline · about 8-12 pages`
- `Standard: 3-4 parties · 3-4 counts or issues · 12-20 key characters · 9-18 month timeline · about 20-30 pages`
- `Complex: 5-7 parties · 5-7 counts or issues · 25-40 key characters · 24-48 month timeline · about 40-60 pages`

Focal point: the scenario TextBox (row 1). It takes all spare height and gets initial focus on entry.

Interaction:
- `CanMoveNext` is true when the trimmed scenario is not empty and not busy. `NextButtonText` = `Next >`.
- `ValidateStepAsync` validates length first. Then, if the scenario hash changed since the last check, it runs `RealEntityDetector` under `LoadingOverlay` (new `LoadingType.EntityCheck`, messages: `Checking for real names`, `Looking for real people and companies`, `Preparing fictional substitutes`). All inputs are disabled while it runs. If entities are found, it opens `EntityReviewDialog` modally, and Cancel in the dialog returns `false` (stays on the step). If none are found, it sets the Green status and proceeds. An unchanged hash reuses the previous decisions and makes no call.

### S2. `EntityReviewDialog` (modal, `FormBorderStyle.FixedDialog`, `StartPosition.CenterParent`, `ClientSize` 720x440, `MinimizeBox`/`MaximizeBox` false, title `Real Names Found`)

Root `TableLayoutPanel`, `Padding = new Padding(8)`:

| Row | SizeType | Content |
|-----|----------|---------|
| 0 | Absolute 64 | Warning banner panel (amber colors above, `Padding = new Padding(16, 8, 16, 8)`): headline 12pt Bold `Your scenario names {n} real people or companies.` plus a 9pt body line `Fictional substitutes will be used in every document and email. Uncheck a row to keep the real name.` |
| 1 | Percent 100 | DataGridView (`RowHeadersVisible = false`, `AllowUserToAddRows = false`, `SelectionMode = FullRowSelect`, `BackgroundColor = SystemColors.Window`) |
| 2 | Absolute 48 | Right-aligned FlowLayoutPanel (RightToLeft flow): `Apply Substitutes` (Primary, 140x32), `Back to Scenario` (Default, 140x32), 8px gap |

Grid columns (in order):
1. `Use fictional name`: CheckBox, width 128, **checked by default**
2. `Name found`: read-only, width 180. Aliases are appended in DimGray: `Walter White (White, Walt)`
3. `Type`: read-only, width 136, values `Person`, `Company`, `Brand`, `Fictional character`, `Fictional organization`
4. `Substitute`: editable TextBox cell, Fill. It is disabled (grey text) when the row is unchecked
- The detector's `reason` shows as the row `ToolTipText`.

Focal point: the entity grid. `Apply Substitutes` is the only accent button.

`AcceptButton` = Apply Substitutes. `CancelButton` = Back to Scenario.

### S3. `StepCoreDocument` (step title: `Review Core Document`)

`this.Padding = new Padding(20)`. Root `TableLayoutPanel`, 1 column, `Padding = new Padding(8)`:

| Row | SizeType | Content |
|-----|----------|---------|
| 0 | Absolute 40 | Header panel: left, document title Label (12pt Bold, `{DocType} — {CourtName}` or `Investigation Memo — {Organization}`). Right-anchored `Regenerate All` (Default, min 120x32) |
| 1 | Percent 100 | `SplitContainer` (vertical split, `SplitterDistance = 240`, `Panel1MinSize = 200`, `SplitterWidth = 8`) |
| 2 | Absolute 28 | Issues caption (9pt Bold): `Issues ({errors} errors, {warnings} warnings)` |
| 3 | Absolute 112 | Issues DataGridView (read-only, columns `Severity` 80, `Section` 180, `Issue` Fill). Error rows ForeColor Red, Warning rows DarkOrange. Double-click selects that section. When there are 0 issues, the grid is hidden and a Green label reads `No issues found. No case-law citations or real names detected.` |
| 4 | Absolute 32 | Progress strip: status Label (fill), `ProgressBar` (width 200, `Continuous`, Maximum = section count), `Cancel Generation` (Danger, 140x32). The ProgressBar and Cancel button are visible only while generating |

SplitContainer Panel1: `ListBox` `Dock = Fill`, `DrawMode.OwnerDrawFixed`, `ItemHeight = 24`, 9pt. One item per section in render order. Item text is `{Heading}` plus a status suffix:
- ` — writing...` (Accent) · ` — pending` (DimGray) · ` — failed` (Red) · ` — {n} issues` (DarkOrange if warnings only, Red if any error) · ` — edited` (default color)
- The selected item uses the Accent background with white text.

SplitContainer Panel2: `TabControl` `Dock = Fill` with two tabs:
- **Tab `Section`**, an inner TableLayoutPanel:
  - Row 0, Absolute 32: selected section heading (12pt Bold)
  - Row 1, Percent 100: section editor TextBox (Multiline, 10pt, `ScrollBars.Vertical`, `WordWrap`, `AcceptsReturn`, `MaxLength = 0`). Paragraphs are shown **without numbers** and separated by one blank line. Code-owned parts (caption, incorporation paragraph, jury demand, signature, memo header) are not editable and do not appear here
  - Row 2, Absolute 32: FlowLayoutPanel: `Apply Edits` (Default, 100x32, enabled only when the text changed), guidance TextBox (10pt, width 320, `PlaceholderText = "Optional guidance, e.g. add the March 3 site meeting"`), `Regenerate Section` (Primary, 150x32). For a Failed section this button reads `Retry Section`
- **Tab `Full Document`**: read-only TextBox (Multiline, 10pt, `ScrollBars.Vertical`, `BackColor = SystemColors.Window`) filled from `CoreDocumentAssembler.RenderPlainText()`. It refreshes when the tab is selected and after every apply or regenerate

Focal point: the section editor TextBox (Section tab). `Regenerate Section` is the only accent button on the screen, apart from the shell's `Next >`/`Finish`.

Interaction:
- **Auto-generate on first entry** when `WizardState.Case.CoreDocument` is null. Generation happens inline, **not** under `LoadingOverlay`: the user watches sections fill in the list and the progress strip counts them. The status label text comes from `IProgress<string>` (`Writing the outline...`, `Writing Factual Allegations (2 of 4)...`, `Writing Count II of IV...`).
- While generating: the editor, Apply, Regenerate Section, Regenerate All and the section list selection are disabled. `CanMoveNext` and `CanMoveBack` are false (raise `StateChanged`). `finally` restores them.
- Edits are applied on `Apply Edits`, on section switch, and on step leave (`Leave` auto-apply). Each apply re-splits paragraphs, sets `IsUserEdited`, increments `Revision`, re-runs `CitationScanner` + leak scan + validator, and refreshes the issues grid and list suffixes.
- Hash mismatch on entry (scenario, preset or preferences changed): show confirm C4 (below). **Yes** regenerates. **No** keeps the document and adds a Warning issue `Document is out of date with the scenario.`
- `NextButtonText` = `Finish` in Phase 2 (the last case-flow step). Phase 3 changes it to `Next >`.

### States (StepCoreDocument)

| State | What is visible |
|-------|-----------------|
| Generating (first run) | List shows the outline's sections as ` — pending`, filling in to done. Editor is empty and disabled. Progress strip is visible |
| Ready | First section selected. Status Green `Document ready: {n} sections, {p} numbered paragraphs.` |
| Ready with issues | As Ready. Status DarkOrange `Document ready with {e} errors and {w} warnings. Review the Issues list.` |
| Partial (some sections failed) | Failed items in Red. Status Red with the section-failure copy. Other sections remain editable |
| Empty (cancelled or fatal before any section was written) | SplitContainer hidden. A centered panel shows the empty-state heading, body and a `Generate Document` Primary button (160x32). Focal point: the centered `Generate Document` button |
| Refused | Empty state with the Refused copy in the body instead of the default body |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Generate Document` (empty state). Per-section primary: `Regenerate Section` (`Retry Section` when failed) |
| Empty state heading | `No core document yet` |

| Error state: substitute blank (dialog) | `Enter a fictional name for {name}, or uncheck the row to keep the real name.` |

|---|--------|-------|------|---------|

| C2 | Regenerate a section with user edits | `Regenerate Section` | `Regenerate "{heading}"? Your edits to this section will be replaced.` | Yes / No |
| C3 | Regenerate All | `Regenerate Document` | `Regenerate the whole document? Every section, including your edits, will be replaced. This makes a new set of Story-model calls.` | Yes / No |

| C5 | Cancel Generation | `Cancel Generation` (Question icon) | `Stop generating? Completed sections will be kept.` | Yes / No |
| C6 | Finish (nothing is persisted in Phase 2) | `Close Case` | `This version does not save the case yet. Closing will discard the scenario and document. Close anyway?` | Yes / No |

# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3 (Case Guide). Generated by gsd-ui-researcher (`--auto`, no user Q&A), verified by gsd-ui-checker.
>
> **Platform:** WinForms desktop (net10.0-windows). All UI is built in code: `InitializeUI()`, a `TableLayoutPanel` root docked `Fill`, row-index comments on every `RowStyle`, and handlers wired only after every control exists.
>
> **Units:** All pixel values are **logical px at 96 DPI**. In code, every one goes through `LogicalToDeviceUnits(n)` on the step or dialog that owns the control. Font sizes are in **points** and scale on their own.
>
> **Visual source of truth:** the accepted redesign in `Helpers/Theme.cs`, `ThemedButton`, `CardPanel`, `SlimProgressBar`, `ButtonHelper` and the reference screen `UserControls/StepCoreDocument.cs` (commit 3dad6bd plus polish 94b6a8d). Visually, this supersedes the 02-UI-SPEC (SystemColors, Color.Red/DarkOrange/Green, 100x35 buttons). **No new palette.** Anything below that is not taken from CONTEXT.md, RESEARCH.md or the reference code is marked **[DEFAULT]** and listed under Assumptions.
>
> **Quality bar (D-04):** the user runs Windows at 150% and has twice rejected unaligned, stock-looking UI. A screen is not done until its 144-DPI render has been inspected against the DPI & Render Contract at the end of this document.

## Spacing Scale

Declared values (multiples of 4), mapped to `Theme` constants:

| Token | Value | Theme constant | Usage in this phase |
|-------|-------|----------------|---------------------|
| xs | 4px | — | Gap between Toggle segments. Gap between a field caption and its field. Subtitle-to-meta gap |
| sm | 8px | `SmallGap` | Gap between adjacent buttons. Gap between the two fields of a paired row (First/Last name, Active from/to). Half-gap margins between side-by-side cards (`Gap / 2`) |
| sm+ | 12px | — | Separation above a card toolbar (after its divider). Status strip top margin. Gap between consecutive fields in a detail panel. Vertical padding of a Case Summary contents row |
| md | 16px | `Gap`, `CardPadding` | Gap between stacked page rows (header, banner, tabs row, body, checks card). **Content x:** every card's first text, dot or control starts 16 from the card's outer edge. In `Padding = 16` cards that is the padding itself. In `Padding = 1` cards (grid, Checks, Recent cases, Contents), every inner left inset is **15** (see Content x below) |
| lg | 24px | `PageMargin` | Page margin (supplied by the shell; steps keep `Padding = 0`). Dialog padding |
| xl | 32px | — | Not used (the empty-state body margin is the inherited 20, see exceptions) |
| 2xl | 48px | — | Not used |

Component dimensions (not spacing tokens; all multiples of 4): button height **34** (every button, including `Mark Reviewed`), compact toggle height **28** (grid-card filter Toggles only; the only button height allowed besides 34), grid row **32**, list item **36** (one-line) and **52** (two-line), Checks card **152**, recent-cases column **296**, empty-state text max width **520**, empty-state marquee **360 x 6**, status-strip progress bar width **220**, detail-panel minimum width **320**, dialog width **520**.

**Content x (one left edge per card).** Every card has exactly one content x: **16 logical px from the card's outer edge**. Compensated values:
- `Padding = 16` cards (detail, banner, case folder, state cards, dialog content): children sit at padding 16 with no extra left margin.
- `Padding = 1` cards (grid cards, Checks card, Recent cases card, Contents card):
  - card header TLP left padding **15**
  - `GridStyle` header and cell left padding **15**. The first column carries the inset. When the first column is the dot column, the dot is drawn at **15** within it.
  - owner-drawn list dot and text inset **15**
  - Checks caption left margin **15**
  - Contents row left padding **15**
  - empty/hint labels inside these cards: left padding **15**
- Right edges mirror this: right padding 16 in `Padding = 16` cards, 15 in `Padding = 1` cards.
- **`StepCoreDocument` moves onto the same x in this phase.** Its left edges currently drift between 13, 16 and 17 px:
  - Sections card header: 16 inside a 1 px card, so text at 17.
  - Issues grid cell and header padding: 12, so text at 13.
  - Section-list dot: 16, so dot at 17.

  Change all three to the compensated 15 values (ideally by switching its issues grid to `GridStyle.Apply`), so every case-flow screen shares one left edge.

Exceptions (inherited from the reference screen for pixel parity; reuse these exact values, do not invent new ones):
- Card header padding: top 14, bottom 10 (`sectionsHeader` in `StepCoreDocument`); left/right 15 inside `Padding = 1` cards (Content x).
- The 15 px insets inside `Padding = 1` cards (Content x; they compensate the card's 1 px padding). List bottom inset 6 inside cards. Subtitle top margin 2. Selection bar width 3. Card divider height 1. Focus-ring inset 3 (drawn by `ThemedButton`).
- `SlimProgressBar` height 6. Status dot diameter 8. Gap from dot to text 10. Guidance/text-field horizontal padding 10.
- Empty-state body bottom margin 20 (reference). New state cards copy this value rather than using 32, so the two screens look identical.
- `CardPanel.Radius` 8 for cards and `Theme.Radius` 6 for buttons and field hosts (existing).

## Typography

WinForms takes line height from the font metrics (about 1.33 for Segoe UI). It cannot be set per control, so the Line Height column shows the effective value.

| Role | Size | Weight | Line Height | Theme factory | Used for |
|------|------|--------|-------------|---------------|----------|
| Small | 9pt | Regular (400) | ~1.33 | `SmallFont()` | Grid column headers, card-header counts, field captions, secondary lines in two-line list items, meta/subtitle lines under detail headings, empty-list hints |
| Body | 9.5pt | Regular (400) | ~1.33 | `BodyFont()` | Grid cells, list items, field values and TextBoxes in detail panels, status strip, banner body, state-card body, page subtitle, all buttons (Default/Toggle) |
| Label | 9.5pt | Bold (700) | ~1.33 | `LabelFont()` | Card captions ("Characters", "Checks", "Case folder"), banner heading, Primary/Danger button text (set by `ThemedButton.Variant`), Case Summary item names |
| Heading | 12pt | Bold (700) | ~1.33 | `HeadingFont()` | Detail-panel entity heading (character name, fact title), state-card heading, dialog headline |
| Title | 15pt | Bold (700) | ~1.33 | `TitleFont()` | Page title in the step header ("Case Guide", the case title on Case Summary) |

**Small text color rule:** Small (9pt) text is always `Theme.TextMuted`. Only these semantic lines use their semantic token instead:
- the Checks no-findings line (`Success`)
- validation messages under detail fields (`Danger`)
- Case Summary line 3: `Saved` / `Exported` in `Success`, `Not saved` in `Danger` (`Not exported yet` stays `TextMuted`)
- the Case Summary `Guide checks` line (`Success` / `Warning` / `Danger`)

No other Small text uses `Text`, `Accent` or a semantic color. Grid column headers are `TextMuted` through `GridStyle`.

That is 4 sizes (9 / 9.5 / 12 / 15) and 2 weights (Regular, Bold). `EditorFont()` (10.5pt) is **not** used on new surfaces. The detail-panel long-text fields use Body 9.5 so a field's caption, value and grid cell look like one family. The existing scenario box on Describe the Case keeps 10.5pt (unchanged). Italic is not used. Never construct `new Font("Segoe UI", ...)` by hand in new code. Use the `Theme` factories.

## Screen Contracts

### S1. `StepCaseGuide` (step title `Case Guide`, NextButtonText `Next >`)

`this.Padding = 0`, `BackColor = Theme.Background`. The shell supplies the 24 margin.

Root `TableLayoutPanel`, 1 column:

| Row | SizeType | Content |
|-----|----------|---------|
| 0 | AutoSize | Header (bottom margin 16) |
| 1 | AutoSize | Banner (hidden when not needed; bottom margin 16 when visible) |
| 2 | AutoSize | Tabs row (bottom margin 16) |
| 3 | Percent 100 | Body host: per-tab grid card + detail card, **or** the full-width state card |
| 4 | Absolute: 152 with findings, or AutoSize with none (see Checks) | Checks card (top margin 16) |
| 5 | AutoSize | Status strip (top margin 12) |

**Row 0, header.** Same structure as the reference header: a 2-column TLP (Percent 100 | AutoSize), 2 rows.
- Title Label: `Case Guide`, `TitleFont`, `Text`, `AutoSize = false`, `Height = PreferredHeight`, `AutoEllipsis`, bottom-left aligned.
- Subtitle Label: `BodyFont`, `TextMuted`, top margin 2, `AutoEllipsis`. Text: `{DisplayPath(folder)} · Saved {h:mm tt}`, e.g. `Documents\ReelDiscovery\Cases\Dunder Mifflin v. Staplex · Saved 3:42 PM`. `DisplayPath` replaces the MyDocuments prefix with `Documents`. When the last save failed, the whole subtitle is `Theme.Danger` and reads `{DisplayPath} · Not saved`. When there is no folder yet (cannot normally happen here), it reads `Not saved yet`.
- Right column (RowSpan 2, anchored right, left margin 16): `Resume Guide` (Default), visible only when any part is Pending or Failed and no run is active.

**Row 1, banner** (`CardPanel`, `BorderColor = Theme.Warning`, `BackColor = Surface`, padding 16). Inner TLP 2 columns (Percent 100 | AutoSize):
- Left: heading (`LabelFont`, `Theme.Warning`) and body (`BodyFont`, `TextMuted`, wraps, `MaximumSize` width tied to the banner width on `SizeChanged`), with 4 between them.
- Right (vertically centered): action buttons, 8 apart.
- Variants (pure helper `StaleBannerText(...)`, unit-tested; stale wins over needs-review):

| Variant | Shown when | Heading | Body | Buttons |
|---------|-----------|---------|------|---------|
| Stale vs core document | `GuideStaleness` reports Issues or Cast stale against the core-document hash, and this hash was not dismissed | `The guide is out of date with the core document.` | `The core document changed after {parts} were written. Update Guide rewrites those parts in order and keeps the entries you edited.` (`{parts}` e.g. `the issues and the cast`) | `Update Guide` (Primary), `Not Now` (Default) |
| Stale downstream | Facts or Values are stale because an upstream part was regenerated | `{Parts} are out of date with the {upstream}.` (e.g. `Key Facts are out of date with the cast.`) | `The {upstream} was regenerated after the {parts} were written. Update Guide rewrites them and keeps the entries you edited.` | `Update Guide` (Primary), `Not Now` (Default) |
| Needs review | No stale part, and 1 or more facts have `NeedsReview` | `{n} facts reference characters you changed.` | `Check that each one still reads correctly, then mark it reviewed.` | `Review Facts` (Default) selects the Key Facts tab, sets its filter to `Needs review` and selects the first such fact |

`Not Now` hides the banner until the basis hash changes again (same idea as `_declinedStaleHash`). The Checks card keeps reporting the stale parts as Warnings. Nothing regenerates silently (D-20).

**Row 2, tabs row.** A 2-column TLP (Percent 100 | AutoSize):
- Left: a `FlowLayoutPanel` of 4 `ThemedButton` Toggles (height 34, 4 apart), exactly one `Selected`. Captions come from the pure helper `TabCaption(part, count, status)`:

| Part status | Caption |
|-------------|---------|
| Ready | `Issues (4)` · `Cast (42)` · `Key Facts (46)` · `Canonical Values (22)` (Cast counts key + background) |
| Generating | `Cast (writing)` |
| Failed | `Cast (failed)` |
| Pending / not written | `Cast` |

- Right: the actions for the selected tab (Default buttons, height 34, 8 apart). These swap when the tab changes:

| Tab | Actions |
|-----|---------|
| Issues | none. `Retry Issue Details` only when the enrichment call failed |
| Cast | `Add Character`, `Regenerate Cast...` |
| Key Facts | `Add Fact`, `Regenerate Facts...` |
| Canonical Values | `Add Value`, `Regenerate Values...` |

All tab actions are disabled while any run is active.

**Row 3, body.** Per tab, a 2-column TLP: **60% grid card | 40% detail card** (margins: grid card right 8, detail card left 8). The detail card has a minimum width of 320. Below that, the grid shrinks and scrolls horizontally.

*Grid card* (`CardPanel`, `Padding = 1`, reference "Sections" card structure):
- Card header TLP (padding 15, 14, 15, 10; 2 columns Percent 100 | AutoSize; **minimum height = 28**, so the header is the same height on every tab and the grids top-align when switching tabs):
  - Left caption (`LabelFont`): `Issues` / `Characters` / `Key facts` / `Canonical values`.
  - Right: a count line (`SmallFont`, `TextMuted`), or compact filter Toggles (height 28, 4 apart) followed by the count:
    - Issues: `From the core document's counts` (pleadings) or `From the memo's findings` (memo).
    - Cast: Toggles `All` · `Key` · `Background`, then `{k} key · {b} background`.
    - Key Facts: Toggles `All` · `Needs review`, then `{n} facts` (plus ` · {r} need review` when r > 0).
    - Canonical Values: `{n} values`.
- Grid (`GridStyle.Apply`), `Dock = Fill`, bottom margin 6, **unbound rows**, `Row.Tag = entity Id`, header-click sorting. A rebuild preserves sort column, direction and selected Id, and is deferred with `BeginInvoke` when triggered from a cell event. The first column on Cast / Key Facts / Values is a 28-wide, read-only, unsortable status-dot column painted in `CellPainting` with `Theme.DrawStatusDot`:
  - `Success`: no findings.
  - `Warning`: warnings, or needs review.
  - `Danger`: errors.
  - `Accent`: being written or regenerated.
  - `BorderStrong`: details not written yet.

| Tab | Columns (logical widths; "Fill w/min" = `AutoSizeMode.Fill` with FillWeight and MinimumWidth) | Editable in grid |
|-----|-----|-----|
| Issues | `ID` 64 · `Source` 88 (`Count I`, `Finding 2`) · `Issue` Fill (min 160) · `Facts` 56 (count, right-aligned) | none (read-only, D-08) |
| Cast | dot 28 · `ID` 64 · `Name` Fill w30/min 120 · `Title` Fill w25/min 100 · `Organization` Fill w25/min 100 · `Tier` 88 (`Key` / `Background`) | `Name`, `Title` |
| Key Facts | dot 28 · `Date` 96 (`yyyy-MM-dd`, sorts chronologically) · `Fact` Fill w45/min 160 · `Issues` 80 (`ISS-01, ISS-03`, tooltip lists titles) · `Who did it` Fill w25/min 96 (names, comma-separated) · `Who knew` 64 (count, tooltip lists names) | `Date`, `Fact` |
| Canonical Values | dot 28 · `ID` 64 · `Kind` 112 · `Label` Fill w35/min 140 · `Value` Fill w30/min 120 · `Facts` 56 | `Label`, `Value` |

  The Key Facts grid has no ID column (the date is the key). The fact ID shows in the detail heading and in Checks. Name cells on Cast carry the email address as `ToolTipText`.
  Grid edit rules: `EditMode = EditOnKeystrokeOrF2`. Commit on `CellEndEdit`, applied with `BeginInvoke` through `CaseGuideEditing`, which sets `IsUserEdited` and triggers autosave. An empty Name/Fact/Label, or an invalid date, cancels the edit, restores the old value, and sets the status line (Danger) to `{Column} cannot be empty.` or `Use a date like 2024-03-03 (YYYY-MM-DD).` Handle `DataError` and never show the stock error dialog. Grid `ErrorText` icons are never used. `Delete` on a selected row runs the same Delete flow as the detail button.
- Empty grid (part Ready but 0 entries): the grid is hidden and a centered `TextMuted` `BodyFont` label reads, per tab: `No characters. Click Add Character or Regenerate Cast...` · `No key facts. Click Add Fact or Regenerate Facts...` · `No canonical values. Click Add Value or Regenerate Values...` · `No issues. Issues come from the core document's counts or findings.`
- Filter with no matches: `No facts need review.` / `No background characters.` (centered `TextMuted`).

## DPI & Render Contract (hard requirement, D-04)

Layout rules:
1. Every literal size goes through `LogicalToDeviceUnits(n)` on the owning step or dialog, including column widths, `MinimumWidth`, `RowTemplate.Height`, `ItemHeight`, paddings, margins, dot sizes, bar sizes and owner-draw insets. Fonts come only from `Theme` factories (points).
2. Content rows are `AutoSize`. Exactly one row per layout is `Percent 100`. `Absolute` is used only for the Checks card (152), dividers (1) and the recent-cases column (296), always scaled.
3. Single-line labels that may be long use `AutoSize = false`, `Height = PreferredHeight` and `AutoEllipsis`. Wrapping labels use `AutoSize = true` with `MaximumSize.Width` updated on the container's `SizeChanged`.
4. Buttons only come from `ButtonHelper.CreateButton(text, 0, LogicalToDeviceUnits(34), style)` (compact toggles: 28). Never set `Width`/`Height`/`Font` afterwards. Text changes re-fit automatically.
5. Buttons on the same row have the same height. Field hosts match the button height (34).
6. Owner-drawn rows measure text with `TextRenderer.MeasureText(..., NoPadding)` before drawing, and reserve the measured width plus 4 slack for right-aligned status text (reference pattern).
7. `CheckedListBox` / `ListBox` heights are computed from `ItemHeight` after the handle exists, never hard-coded.
8. AutoScroll detail panels: inner TLP width = `ClientSize.Width` on `ClientSizeChanged`. No horizontal scrollbar is ever visible in a detail panel.
9. Inside cards, no control shows a stock 3D or FixedSingle border: TextBoxes `BorderStyle.None` inside `TextFieldHost`, grids/lists `BorderStyle.None`.
10. Alignment:
    - Every card's content starts at Content x = 16 from the card's outer edge (15 inset inside `Padding = 1` cards). Within one card, the caption, grid header text, first-column cell text, status dots, list text and detail fields all share that x. Render inspection measures it: tolerance 0 px at 96 DPI, 1 device px at 144 DPI.
    - Grid cell text and header text start at the same x (padding 15 on both).
    - The page title's left edge aligns with every card's left edge (the shell's 24 margin).
    - The rightmost header button's right edge aligns with the cards' right edge.
    - Grid card headers have identical heights across tabs.

Render check (UI tasks; `[Trait("Category","Render")]`, harness per RESEARCH Wave 0):
- STA thread, `SetProcessDpiAwarenessContext(-4)` before any window. Skip unless `DeviceDpi == 144`.

# Phase 4 — UI Design Contract

> Visual and interaction contract for Phase 4 (Corpus Plan & Answer Key). Generated by gsd-ui-researcher (`--auto`, no user Q&A), to be verified by gsd-ui-checker.
>
> **Platform:** WinForms desktop (net10.0-windows). All UI is built in code: `InitializeUI()`, a `TableLayoutPanel` root docked `Fill`, row-index comments on every `RowStyle`, and handlers wired only after every control exists (init-order null refs have bitten twice).
>
> **Units:** All pixel values are **logical px at 96 DPI**. In code, each one goes through `LogicalToDeviceUnits(n)` on the step, dialog or custom control that owns it. Font sizes are in **points** and come only from `Theme` factories.
>
> **Baseline:** `03-UI-SPEC.md` (approved 2026-10-01) is the design system for this phase. Its palette, type scale, spacing tokens, Content x rule, `GridStyle`, `TextFieldHost`, `ThemedDialog`, state card, banner, Checks card, status strip, `Plural` helper, tone rules and DPI & Render Contract **apply unchanged** and are not repeated in full here. This document only adds what Phase 4 needs. Anything not taken from 04-CONTEXT.md, 04-RESEARCH.md, 03-UI-SPEC.md or the existing code is marked **[DEFAULT]** and listed under Assumptions.
>
> **Quality bar (D-03):** the user runs Windows at 150% and has rejected unaligned, stock-looking UI more than once. A screen is not done until its 144-DPI render has been inspected against the DPI & Render Contract at the end of this document.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (WinForms; shadcn does not apply) |
| Preset | not applicable |
| Component library | In-repo theme (unchanged): `Theme` tokens, `ThemedButton` via `ButtonHelper.CreateButton` (Default / Primary / Danger / Toggle), `CardPanel`, `SlimProgressBar`, `GridStyle`, `TextFieldHost`, `ThemedDialog`. New in this phase: `PercentSlider` and `MonthHistogram` (custom-painted controls, specs below) |
| Icon library | none. Text only, plus painted 8 px status dots and the histogram legend dots. No glyphs, chevrons, emoji or image icons |
| Font | Segoe UI (`Theme.FontFamily`) everywhere |

**Shell changes.** The case flow becomes 7 steps: API Configuration, Describe the Case, Review Core Document, Case Guide, **Corpus Settings**, **Review Plan**, Case Summary. The header band reads `Step 5 of 7: Corpus Settings` and `Step 6 of 7: Review Plan`. `CaseStage` gains `CorpusSettings` and `ReviewPlan`, inserted before `Summary` and mapped to step **types** (never indexes). Recent-cases stage labels (`CaseGuideUiText.StageLabel`) add `Corpus settings` and `Plan review`.

**Real content size.** WizardForm opens at a 1150x900 logical client (minimum 1000x700). After the 64 header band, the 66 nav bar, the 30 footer and the 24 top/left/right page margin, a step gets about **1102 x 716** at the default size and **952 x 516** at the minimum. Every layout below is budgeted against both.

### Shared components to add

| Component | File | Purpose |
|-----------|------|---------|
| `PercentSlider` | `Helpers/PercentSlider.cs` (new `Control`) | Themed replacement for `TrackBar` (RESEARCH anti-pattern: stock TrackBar shows system chrome and scales badly). Spec below |
| `MonthHistogram` | `UserControls/MonthHistogram.cs` (new `Control`) | Custom-painted stacked month histogram (RESEARCH: no charting package on modern .NET). Spec below |
| `StatTile` | `UserControls/StatTile.cs` (new `UserControl`) | One stat tile on Review Plan (caption, value, sub-line) |
| `CorpusUiText` | `UserControls/CorpusUiText.cs` (new, pure static) | All Phase 4 copy that contains counts, dates or conditions. Unit-tested like `CaseGuideUiText` |

**`PercentSlider`** (height **28**, `Dock = Fill` in its cell, `TabStop = true`, `DoubleBuffered`):
- Track: 4 px tall, fully rounded, vertically centered. The unfilled part is `Theme.Border`. The filled part from the left end to the thumb is `Theme.Accent` (`TextDisabled` when disabled).
- Thumb: a 16 px circle, `Theme.Surface` fill, 2 px `Theme.Accent` border (`AccentHover` on hover, `AccentPressed` while dragging, `BorderStrong` when disabled). Its center travels from x = 8 to x = width − 8, so the thumb never clips.
- Focus: a 24 px `Theme.AccentSoft` halo behind the thumb while focused. No dotted focus rectangle.
- Range `Minimum = 5`, `Maximum = 60`, step 1 (RESEARCH Pattern 1). Input: drag the thumb, click the track to jump, Left/Right ±1, PageUp/PageDown ±5, Home/End. Raises `ValueChanged` live while dragging. The owning step commits to the draft (autosave) on mouse-up, on key-up and on `Leave`, never on every drag tick.
- All sizes go through `LogicalToDeviceUnits`. Painting is anti-aliased.

**`MonthHistogram`** (`Dock = Fill`, `DoubleBuffered`, `ResizeRedraw`):
- Data: a list of `(month, relevant, nonRelevant)` buckets from `PlanSummary`, one per calendar month from window start to window end inclusive (up to 51 buckets for a 48-month timeline plus lead-in and tail). Months with no email still get a bucket (zero height).
- Plot area: insets top 8, right 15, bottom = Small font height + 8 (x-label band), left = y-gutter width.
- Y axis: three horizontal gridlines at 0, half and max (1 px `Theme.Border`). Max is a "nice" number ≥ the tallest bucket (1, 2, 5 × 10^k; pure helper `NiceAxisMax`). Labels are `SmallFont`, `TextMuted`, `N0`, right-aligned in a gutter that starts at Content x (15 inside the `Padding = 1` card) and is as wide as the widest measured label + 8.
- Bars: bucket width = plot width / bucket count. Bar width = max(2, round(bucket width × 0.7)), centered in the bucket, square corners. Each bar is stacked: **Relevant at the bottom in `Theme.Accent`**, Not relevant on top in `Theme.TextDisabled` (#A0A7B0), so relevant volume reads against a common baseline.
- X labels: `MMM yy` (`Mar 24`), `SmallFont`, `TextMuted`, centered under their bucket. Label every k-th bucket, starting with the first, where k is the smallest of 1, 2, 3, 6, 12 for which (widest measured label + 8) ≤ k × bucket width (pure helper `HistogramLabelStep`). Labels never overlap or clip at either edge (clamp the first and last label inside the plot).
- Hover: the bucket under the mouse gets a `SurfaceMuted` column background, and a `ToolTip` reads `March 2024: 46 relevant, 120 not relevant (166 emails)`.
- Empty plan (cannot normally happen): nothing painted except the axis.

**`StatTile`** (`CardPanel`, padding **16 horizontal, 12 vertical**, `Dock = Fill`). Three AutoSize rows:
- Caption: `SmallFont`, `TextMuted`, `AutoEllipsis`, single line.
- Value: `TitleFont` (15pt Bold), `Text`, top margin 4, `AutoEllipsis`.
- Sub-line: `SmallFont`, `TextMuted`, top margin 2, `AutoEllipsis`.
- The tile sets a `ToolTip` with the full caption, value and sub-line (and the cost breakdown on the cost tile), so nothing is lost if a label ellipsizes.

## Typography

Unchanged from Phase 3: 4 sizes, 2 weights. WinForms takes line height from font metrics (~1.33 for Segoe UI).

| Role | Size | Weight | Line Height | Theme factory | Used for in this phase |
|------|------|--------|-------------|---------------|------------------------|
| Small | 9pt | Regular (400) | ~1.33 | `SmallFont()` | Field captions, hints under fields, tile captions and sub-lines, grid column headers, histogram axis labels and legend, Checks hint, notice rows, Case Summary line 2/3 |
| Body | 9.5pt | Regular (400) | ~1.33 | `BodyFont()` | Field values, live count line, checkbox text, grid cells, banner body, state-card body, stage checklist, status strip, page subtitle, Default/Toggle buttons |
| Label | 9.5pt | Bold (700) | ~1.33 | `LabelFont()` | Card and section captions (`Corpus size`, `Relevant emails`, `Date window`, `Attachments`, `Advanced`, `Emails by month`, `Counts`, `Checks`), banner heading, approval badge, Primary/Danger button text, Case Summary item names |
| Heading | 12pt | Bold (700) | ~1.33 | `HeadingFont()` | State-card heading, dialog headline |
| Title | 15pt | Bold (700) | ~1.33 | `TitleFont()` | Page titles (`Corpus Settings`, `Review Plan`) and **stat-tile values** |

**Small text color rule** (extends Phase 3's list). Small text is always `Theme.TextMuted`, except these semantic lines:
- the Checks no-findings line (`Success`)
- validation messages under fields, and the mix total when it is not 100 (`Danger`)
- the low-relevant warning under the slider and the date-clamp notice (`Warning`)
- the mix total when it is 100 (`Success`)
- Case Summary line 3 on the new rows: `Written {time}` / `Approved {time}` (`Success`), `Out of date ...` (`Warning`), `Could not write ...` (`Danger`)

Italic is not used. `EditorFont()` is not used. Never construct `new Font(...)` by hand in new code.

`this.Padding = 0`, `BackColor = Theme.Background`. The shell supplies the 24 margin.

Root `TableLayoutPanel`, 1 column:

| Row | SizeType | Content |
|-----|----------|---------|

| 1 | AutoSize | Notice line (bottom margin 16) |

| 3 | AutoSize | Status strip (top margin 12): status `Label` only (`BodyFont`, `MinimumSize` height 34, `AutoEllipsis`) |

Inner TLP (inside the scroll host):

| Row | SizeType | Content |
|-----|----------|---------|
| 0 | AutoSize | Two-card row: 2-column TLP, Percent 50 / Percent 50. Left card margin right 8, right card margin left 8. Both cards `Dock = Fill`, so they are the same height |
| 1 | AutoSize | Advanced card (top margin 16) |

**Row 0, header.** Same structure as Case Guide: 2-column TLP (Percent 100 | AutoSize), 2 rows.
- Title `Corpus Settings` (`TitleFont`, `AutoEllipsis`, `Height = PreferredHeight`).
- Subtitle (`BodyFont`, `TextMuted`, top 2): `{DisplayPath(folder)} · Saved {h:mm tt}` (same helper as Case Guide; `Not saved` variant in `Danger`).
- Right (RowSpan 2, anchored right): `Reset to Defaults` (Default, height 34).

**Row 1, notice line** (`SmallFont`, `TextMuted`, wraps; `MaximumSize` width tied to the step width). Pure helper `CorpusUiText.SettingsNotice(plan state)`:

| Plan state | Copy |
|-----------|------|
| No plan | `Click Next to plan every thread and message from these settings and the case guide. Nothing is written yet.` |
| Plan exists, not approved | `Changing these settings replaces the current plan when you click Next.` |
| Plan approved | `The plan was approved on {MMM d, yyyy}. If you change these settings, Review Plan offers to re-plan; the approved plan stays until you do.` |

**Left card: `Size and relevance`** (`CardPanel`, padding 16). Inner TLP, AutoSize rows:

| Row | Content |
|-----|---------|
| 0 | Section caption `Corpus size` (`LabelFont`, bottom 8) |
| 1 | Size row: 3-column TLP (AutoSize | AutoSize | Percent 100). Col 0: `FlowLayoutPanel` of 4 Toggles `250` · `1,000` · `2,500` · `5,000` (height 34, 4 apart). Col 1: `TextFieldHost` number field, width 96, left margin 8, digits right-aligned, `N0` formatted on `Leave`. Col 2: empty |
| 2 | Hint (`SmallFont`, `TextMuted`, top 4, wraps): `Default for a {Simple/Standard/Complex} case: {250/1,000/2,500} emails. Type any number from 50 to 5,000.` |
| 3 | Section caption `Relevant emails` (`LabelFont`, top 16, bottom 8) |
| 4 | Slider row: 3-column TLP (Percent 100 | AutoSize | AutoSize). `PercentSlider` (vertically centered against the field) · number field width 72, left margin 12 · `%` suffix label (`BodyFont`, `TextMuted`, left margin 4, vertically centered) |
| 5 | Live counts (`BodyFont`, `Text`, top 8): `≈200 relevant / 800 non-relevant emails` |
| 6 | Relevant warning (`SmallFont`, wraps, top 4; hidden when not needed). See D-07 copy below |

Size interaction:
- Clicking a preset Toggle sets the number field and selects that Toggle. Typing in the number field selects the matching Toggle when the value equals a preset, otherwise none.
- The number field commits on `Leave` and `Enter`. Non-digits are ignored (commas allowed). Values outside 50-5,000 are clamped, and the hint line is replaced for that commit by `SmallFont` `Warning`: `Set to {clamped:N0}. The corpus size must be 50 to 5,000 emails.` An empty field restores the previous value.
- Default on first entry: from `draft.Complexity` (Simple 250, Standard 1,000, Complex 2,500) (D-06).

Relevant interaction:
- The slider and the % field stay in sync. The field accepts 5-60 and clamps like the size field.
- Live counts update on every slider tick and size change, through the **same** pure function the allocator uses (`CorpusSettings.RelevantCount`), so the screen and the plan agree (RESEARCH Pitfall 4). Format: `≈{r:N0} relevant / {n:N0} non-relevant emails`.
- Relevant warning (D-07; pure helper `CorpusUiText.RelevantWarning(relevant, datedFacts)`):

| Condition | Copy | Color |
|-----------|------|-------|
| relevant < dated key facts | `Only {Plural(r, "relevant email")} for {Plural(f, "key fact")}. Every key fact needs at least one relevant email: raise this to at least {p}%.` | `Warning` |
| relevant < 2 × dated key facts | `Most key facts will get a single short email. Raise this to {p2}% or more for fuller threads.` | `TextMuted` |
| otherwise | hidden | — |

`{p}` and `{p2}` are the smallest whole percentages that clear each threshold at the current size (capped at 60). The warning never blocks Next (the planner still plans one thread per fact, RESEARCH Pitfall 9).

**Right card: `Dates and attachments`** (`CardPanel`, padding 16). Inner TLP, AutoSize rows:

| Row | Content |
|-----|---------|
| 0 | Section caption `Date window` (`LabelFont`, bottom 8) |
| 1 | Date row: 3-column TLP (Percent 50 | Percent 50 | AutoSize). Each date column: caption (`SmallFont`, `TextMuted`, bottom 4) `Start` / `End` above a single-line `TextFieldHost` (height 34, `PlaceholderText = "YYYY-MM-DD"`). Column gap 8. Col 2: `Reset Window` (Default, height 34, left margin 8, bottom-aligned with the fields) |
| 2 | Window hint (`SmallFont`, `TextMuted`, top 8, wraps): `Key facts run from {MMM d, yyyy} to {MMM d, yyyy}. The default window adds about a month before and two months after for everyday email.` |
| 3 | Clamp/validation line (`SmallFont`, top 4, hidden unless needed) |
| 4 | Section caption `Attachments` (`LabelFont`, top 16, bottom 8) |
| 5 | 2 x 2 TLP (Percent 50 / Percent 50) of CheckBoxes, row gap 8: `Office documents` · `Calendar invites` / `Images` · `Voicemail` |
| 6 | Media notice (`SmallFont`, `TextMuted`, top 8, wraps; only when no tested OpenAI key): `Images and voicemail need a tested OpenAI key. Add one on the API Configuration step to turn them on.` |
| 7 | Attachment hint (`SmallFont`, `TextMuted`, top 8, wraps): `Office documents are Word, Excel and PowerPoint files. The plan only gives attachments of the types you check.` |

CheckBoxes copy the `RegenerateTabDialog` pattern: `AutoSize = true`, `FlatStyle = FlatStyle.System`, `BodyFont`, `ForeColor = Theme.Text`, **`BackColor = Theme.Surface`** (inside a card), `UseMnemonic = false`. With no tested OpenAI key, `Images` and `Voicemail` are unchecked and disabled. The user's saved choice is kept and re-applied when a key appears (effective value re-evaluated on every enter, RESEARCH Pitfall 13).

Date interaction (D-10):
- Defaults: first key fact − 1 month to last key fact + 2 months.
- Fields commit on `Leave`. An unparseable date turns the host border `Danger` and the line reads (`Danger`) `Use a date like 2024-03-03 (YYYY-MM-DD).` The value is not committed.
- A start after the first key fact (or an end before the last) is clamped. The field shows the clamped date and the line reads (`Warning`) `Start moved to {MMM d, yyyy}, the first key fact. The window must include every key fact.` (or `End moved to ..., the last key fact. ...`).
- End before start: `Danger`, `The end date must be after the start date.`, not committed.
- `Reset Window` restores the default window without a prompt.

**Row 1, Advanced card** (`CardPanel`, `Padding = 1`). Inner TLP:

|-----|----------|---------|
| 0 | AutoSize | Header (padding 15, 14, 15, 10): 3-column TLP (AutoSize | Percent 100 | AutoSize). Caption `Advanced` (`LabelFont`) · summary (`SmallFont`, `TextMuted`, left margin 12, `AutoEllipsis`, vertically centered) · `Show Advanced` / `Hide Advanced` (Default, height 34) |

*Left column, `Non-relevant mix`* (D-08). Caption `Non-relevant mix` (`LabelFont`, bottom 4), then a hint (`SmallFont`, `TextMuted`, bottom 12): `How the {n:N0} non-relevant emails are split.` Then a 3-column TLP (Percent 100 | Absolute 64 | AutoSize), one row per share, row gap 8:

| Label (`BodyFont`, `Text`, vertically centered) | Default |
|------|---------|
| `Custodians' daily business` | 50 |
| `Ancillary staff traffic` | 20 |
| `Newsletters, spam and personal` | 20 |

The four shares must add up to 100%.` in `Danger` (Next is blocked, M-S1). Under that (`SmallFont`, `TextMuted`, top 4): `Near-miss decoys mention the same projects and people but are not about the alleged conduct.` and `Use Default Mix` (Default, height 34, top 12, left-aligned).

*Right column, `Overrides`* (D-09). Caption `Overrides` (`LabelFont`, bottom 4), hint (`SmallFont`, `TextMuted`, bottom 12): `Leave a field empty to let the planner choose.` Then a 2-column TLP (Percent 100 | Absolute 96), row gap 8; each row is a label (`BodyFont`, `Text`) above (Small) hint text in column 0, and the field in column 1 (vertically centered on the label + hint pair):

| Label | Field | Placeholder / range | Hint (`SmallFont`, `TextMuted`) |
|-------|-------|---------------------|-------------------------------|
| `Hot emails per hot fact` | number | `Auto`, 1-5 | `Auto: 1 or 2 each, about {n} hot emails from {Plural(f, "hot fact")}.` |
| `Privileged share of relevant threads` | number + `%` suffix | `Auto`, 0-30 | `Auto: about 8%, threads with {counsel names, max 2, then "and {n} more"}.` When the cast has no counsel: `No counsel in the cast, so no privileged threads are planned.` and the field is disabled |
| `Attachment rate` | number + `%` suffix | `Auto`, 0-60 | `Auto: 20% of emails carry an attachment.` |
| `DocID prefix` | text, 2-6 letters | derived prefix as placeholder | `DocIDs will read {PREFIX}-000001, attachments {PREFIX}-000001.0001.` |

Override fields commit on `Leave`. Out-of-range numbers clamp with a `Warning` line under that row: `Set to {v}. Use {min} to {max}.` The DocID prefix uppercases input and accepts A-Z only. Invalid (fewer than 2 letters): `Danger` border and `Use 2 to 6 letters, e.g. DM.`, not committed. Empty = derived prefix.

**Interaction rules**
- Everything autosaves on commit (D-04). The subtitle shows `Saved {time}`.
- `Reset to Defaults` asks C-S1, then restores every setting (size from complexity, 20%, default window, all available media on, default mix, overrides automatic, derived prefix) and collapses Advanced.
- **Next gate** (`ValidateStepAsync`): flush pending field commits first. Mix total ≠ 100 → M-S1 (blocked). Invalid date field → M-S2 (blocked). Otherwise advance to Review Plan, which plans automatically when needed (D-12, RESEARCH A13).
- `< Back` returns to Case Guide.
- Keyboard: Tab order follows header → size Toggles → size field → slider → % field → Start → End → Reset Window → checkboxes → Show Advanced → mix fields → Use Default Mix → override fields. Arrow keys move the slider when it has focus.

**Interaction rules**
- **Entering the step** (`OnEnterStepAsync`), first match wins:
  1. A planning run is active → keep showing it.
  2. No plan → start planning automatically (D-12, RESEARCH A13).
  3. Plan exists, not approved, settings hash differs → re-plan automatically with no guidance.
  4. Plan approved, settings hash differs, not dismissed → show the settings-changed banner.
  5. Guide hash differs, not dismissed → withdraw approval and show the stale banner.
  6. Otherwise → show the plan.
- **During a run** (D-18): `CanMoveNext` / `CanMoveBack` are false (raise `StateChanged`), header buttons hidden. `Cancel Planning` asks C-P1. A cancelled or failed run discards the new plan; settings are untouched. Disposing the step cancels the run. `finally` restores state and is a no-op after dispose (WR-07 pattern).
- **Re-plan** (`Re-plan...` in the header or banner) opens D-RP. OK starts the run with the guidance text.
- **Approve Plan** (D-26): no confirm. Disable header buttons and Next; status `Writing the answer key and review protocol...` (`Accent`, no bar: it is a fast file write because the protocol prose is written during planning, RESEARCH A14). Write `answer-key.csv`, `answer-key.xlsx` and `{folder name} - Review Protocol.docx` atomically into the case folder, then set `Approved`, advance `CaseStage` to `ReviewPlan`, save, and show the badge. On failure nothing is marked approved.
- **Next gate** (`ValidateStepAsync`): run active → Next disabled. No plan → M-P1 (blocked). Plan not approved → M-P2 (Yes approves, then continues; No stays). Approved → advance to Case Summary.
- `< Back` returns to Corpus Settings (enabled whenever no run is active).

# Phase 7 — UI Design Contract

> Visual and interaction contract for Phase 7 (Scale, Cost, QA & Cutover). Generated by gsd-ui-researcher in `--auto` mode: no user Q&A. Every value comes from 07-CONTEXT.md, 07-RESEARCH.md, the approved 03/04/05/06 UI-SPECs or the current code. Where none of them answered, the value is marked **[DEFAULT]** and listed under Assumptions. Verification by gsd-ui-checker follows.
>
> **Platform:** WinForms desktop. All UI is built in code: `InitializeUI()`, a `TableLayoutPanel` root docked `Fill`, row-index comments on every `RowStyle`, and handlers wired only after every control exists.
>
> **Units:** All pixel values are **logical px at 96 DPI**. Each one goes through `LogicalToDeviceUnits(n)` (or `ThemedDialog.LDU`) on the owning control. Font sizes are in **points** and come only from `Theme` factories. Fixed device-pixel sizes are forbidden (D-04, the Phase 6 model-dialog bug).
>
> **Baseline:** this phase **extends `06-UI-SPEC.md` (approved)** and through it 05-, 04- and 03-UI-SPEC. Palette, type scale, spacing tokens, Content x rule, `GridStyle`, `CardPanel`, `StatTile`, `SlimProgressBar`, banners, state cards, status strip, `ThemedDialog`, `Plural` helper, tone rules, the confirmation format and DPI & Render Contract rules 1-25 **all apply unchanged** and are not repeated. This document covers only what Phase 7 adds or changes. No screen is redesigned.
>
> **Quality bar (D-04):** the user runs Windows at 150%. A screen is not done until its 144-DPI render has been inspected by eye against the DPI & Render Contract.
>
> **Sample copy rule:** examples use placeholders (`{subject}`, `{model}`, `{PREFIX}-000123`). Generated content keeps guide names verbatim (D-03); UI copy never invents names.

| Warning | `Theme.Warning` | Leakage `Warning`; scans with findings; blind review with disagreements or same-provider fallback; batch hint when batch is checked; "Batch finished with failures" and "Batch failed at the provider" activity dots |

| Pending / not run | `Theme.BorderStrong` | QA rows not run yet; leakage `Not enough data` |

**Leakage `Fail` is Danger, scan findings are Warning:** the leakage verdict is a pass/fail measurement with stated thresholds; scan findings and blind-review disagreements are items to check, not failures. None of them blocks export (D-15).

Accent is reserved for:
1. Primary buttons, **at most one visible at a time** per surface besides the shell's `Next >`: the Phase 6 list unchanged, plus `Start Review` (BlindReviewDialog) and `Regenerate Thread...` (QaFindingsDialog, enabled only with a selected row). Case Summary adds **no** Primary button: every new row button is Default (or Danger for `Cancel Review`).
2. `SlimProgressBar` fill.
3. In-progress status text, the running stage row's dot (also while it waits on a batch), batch-submitted activity dots, and blind review running line 3.
4. Grid selection (`AccentSoft`), the checkbox check mark (system-drawn), and the keyboard focus ring.

Accent is never used for links, headings, card borders, captions, tile values, secondary buttons or completed states.

The `Quality checks` group sits between Corpus and Case guide because it reports on the corpus [DEFAULT].

**R1. `Generation cost` (new, Corpus group, no buttons).**
- Line 2: `What this case has cost so far, across all sessions.`
- Line 3 (`QaUiText`/`GenerationUiText.CostRow`): not generated → `Nothing spent yet` (Muted); otherwise `${total:0.00} spent · input ${i:0.00} · cache write ${w:0.00} · cache read ${r:0.00} · output ${o:0.00} · batch discount −${b:0.00} · images and voicemail ${m:0.00}` (Muted; zero clauses after the total are dropped).
- Line 3 tooltip: the same breakdown, one item per line (format of S6). Values come from journal lines (`CostUsd`, optional `CacheWriteTokens`/`CacheReadTokens`/`BatchSavingsUsd`) so the row survives restarts.
- Dot: `BorderStrong` when nothing spent, `Success` otherwise.

**R2. `Consistency scans` (new; D-15, runs automatically at run end).**
- Line 2: `Free checks for mentions of facts dated after the email and values that contradict the case guide. They run at the end of every run.`
- Line 3 states:

| State | Line 3 | Tone / dot |
|-------|--------|------------|
| No run yet | `Not run yet. They run when the emails are generated.` | Muted / BorderStrong |
| Clean | `No problems in {Plural(n, "scanned email")}` | Success |
| Findings | `{Plural(f, "flagged email")} in {Plural(t, "thread")}: {x:N0} timeline, {y:N0} value, {z:N0} story-detail` (zero clauses dropped) | Warning |
| Out of date (corpus changed since the scan) | `Last scan is older than the corpus. It runs again at the end of the next run.` | Muted / BorderStrong |

- Button: `View Findings` (Default; visible when findings exist). Opens S3 in scan mode.

**R3. `Leakage audit` (new; D-14).** Runs automatically with the scans at run end (free, seconds) [DEFAULT] and on demand.
- Line 2: `Checks whether sender, dates, recipients, attachments, thread depth or privilege marks alone can tell relevant mail from non-relevant mail.`
- Line 3 (`QaUiText.LeakageLine`):

| Verdict | Line 3 | Dot |
|---------|--------|-----|
| Not run | `Not run yet.` | BorderStrong |
| Pass (balanced accuracy ≤ 60%) | `Pass: metadata alone predicts relevance {ba:0}% of the time (50% is a coin flip).` | Success |
| Warning (> 60% and ≤ 70%) | `Warning: metadata alone predicts relevance {ba:0}% of the time. Top signal: {signal}.` | Warning |
| Fail (> 70%) | `Fail: metadata alone predicts relevance {ba:0}% of the time. Top signal: {signal}.` | Danger |
| Not enough data | `Not enough data: the audit needs 40 relevant and 40 non-relevant emails; this corpus has {r:N0} and {n:N0}.` | BorderStrong |

- Line 3 tooltip: `Balanced accuracy of a simple model trained on metadata only, tested on threads it did not see (5-fold). Pass is 60% or lower, Warning is above 60% up to 70%, Fail is above 70%. Some signal is normal: real custodians and the dispute dates also predict relevance.` Thresholds are research A4 [ASSUMED]; the copy reads them from the same constants the audit uses.
- Buttons: `View Report` (Default; visible once run), `Run Audit` (Default; always visible when the corpus has generated emails). Run Audit shows `Running the leakage audit...` in the status strip (Accent) and needs no confirmation (free, read-only).
- `{signal}` formats (`QaUiText.SignalText`): `{feature}: only on relevant mail`, `{feature}: never on relevant mail`, `{feature}: {p:0}% relevant vs {base:0}% overall`. Feature names in plain words: `privilege banner`, `privileged subject tag`, `sender {address}`, `{n} or more CC recipients`, `sent on {weekday}`, `sent {hour bucket}` (`before 8 AM`, `8 AM to 6 PM`, `after 6 PM`), `subject length {bucket}`, `{kind} attachment`, `thread depth {n}+`.

**R4. `Blind review` (new; D-11, D-12).**
- Line 2: `A second model labels a sample of emails without seeing the answer key. Disagreements are listed for you to check.`
- Line 3 states:

| State | Line 3 | Tone / dot |
|-------|--------|------------|
| Not run | `Not run yet. About ≈${c} to review {Plural(n, "email")} with {model}.` | Muted / BorderStrong |
| Running | `Reviewing: {d:N0} of {Plural(n, "email")}...` | Accent / Accent |
| Stopped part way | `{d:N0} of {Plural(n, "email")} reviewed; the review stopped. Run Blind Review again to finish the rest.` | Warning |
| Done, agreement | `{Plural(n, "email")} reviewed by {model}: all agree with the answer key{fallback}` | Success (Warning when `{fallback}` shows) |
| Done, disagreements | `{Plural(n, "email")} reviewed by {model}: {Plural(k, "disagreement")} ({p:0}% agree){fallback}` | Warning |

`{fallback}` = ` · same provider as the corpus` when the reviewer fell back (D-12); its tooltip: `Only one provider key was tested, so the reviewer came from the provider that wrote the corpus and is less likely to notice its writing habits.`

Done: `Blind review finished: {Plural(k, "disagreement")}.` (Success when 0, else Warning). Error: `Blind review stopped: {message}. Reviewed emails are kept; run it again to finish.` (Danger).

**Row empty state rule.** Before any email is generated, all three QA rows show their Not run line and only `Run Blind Review...` / `Run Audit` are hidden (nothing to check yet).

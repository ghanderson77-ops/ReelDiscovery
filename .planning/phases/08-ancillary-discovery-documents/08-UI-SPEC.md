# Phase 8 — UI Design Contract

> Visual and interaction contract for Phase 8 (Ancillary Discovery Documents). Generated by gsd-ui-researcher in `--auto` mode with no user Q&A. Every value comes from 08-CONTEXT.md (D-01..D-30), 08-RESEARCH.md, the approved 03-07 UI-SPECs, or the current code. Where none of them answered, the value is marked **[DEFAULT]** or **[ASSUMED]** and listed under Assumptions. gsd-ui-checker verifies it next.
>
> **Platform:** WinForms desktop. All UI is built in code: `InitializeUI()`, a `TableLayoutPanel` root docked `Fill`, a row-index comment on every `RowStyle`, and handlers wired only after every control exists (research Pitfall 8).
>
> **Units:** All pixel values are **logical px at 96 DPI**. Each one goes through `LogicalToDeviceUnits(n)` (or `ThemedDialog.LDU`) on the owning control. Font sizes are in **points** and come only from `Theme` factories. Fixed device-pixel sizes are forbidden (D-03).
>
> **Baseline:** this phase **extends `07-UI-SPEC.md` (approved)** and, through it, the 06/05/04/03 UI-SPECs. The following all apply unchanged and are not repeated here: the palette, type scale, spacing tokens, Content x rule, `GridStyle`, `CardPanel`, `SlimProgressBar`, banners, state cards, the status line, `ThemedDialog`, `TextFieldHost`, the `Plural` helper, the tone rules, the confirmation format, and DPI & Render Contract rules 1-33. This document covers only what Phase 8 adds or changes.
>
> **Quality bar (D-03):** the user runs Windows at 150%. A screen is not done until its 144-DPI render has been inspected by eye against the DPI & Render Contract.
>
> **Sample copy rule:** examples use placeholders (`{name}`, `{party}`, `{model}`). Generated content keeps guide names verbatim, including names from fictional works (D-02). UI copy never invents names.

- **Run button:**

No confirmation, because the cost is on screen (07 U-precedent).
  - Running: the same slot shows `Cancel Generation` (**Danger**), which asks C-D1.
  - Focus: on entry, `Generate Documents` has focus when it is enabled. Otherwise the witness grid has focus.

**Interaction rules.**
- Every input (witness checks, fields, checkboxes, combos) writes `CaseDraft.Discovery` on change and sets `UserTouched = true`. The case is saved through the existing case-save path (`ValidateStepAsync` also saves; it never blocks Next). The Documents grid and the estimate refresh on every change, with a 250 ms debounce for text fields [DEFAULT].
- **During a run:** every input, both row buttons and `Open Discovery Folder` are disabled. The grid stays scrollable and selectable. `CanMoveNext = false` and `CanMoveBack = false` (D-07: Next is enabled except while generating). Rows move from `Not generated` to `Writing...` to their outcome as each document finishes. Each finished document is saved (.docx, then sidecar) before the next status update.
- `OnEnterStepAsync` rebuilds eligibility, defaults (while untouched), corpus detection, staleness and the grid from the current draft and sidecar. It is never slow enough to need `LoadingOverlay`. If it is, the grid shows `Loading...` in its empty-text slot [DEFAULT].
- Unchecking a witness or a set does **not** delete a saved document: its row stays (it is in the sidecar). Files are never deleted from this screen [DEFAULT].
- Settings changed after a document was written do not mark it out of date. `Regenerate...` uses the current settings, and the dialog states them (S2).

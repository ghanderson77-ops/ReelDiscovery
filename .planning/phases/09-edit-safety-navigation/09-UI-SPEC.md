# Phase 9 — UI Design Contract

> Visual and interaction contract for Phase 9 (Edit Safety & Navigation, gap closure W1, W2, W3, W6). Generated by gsd-ui-researcher in `--auto` mode with no user Q&A. Every value comes from 09-RESEARCH.md, the approved 02-08 UI-SPECs, or the current code (`Helpers/Theme.cs`, `CaseGuideUiText`, `CorpusUiText`, `GenerationUiText`, `DiscoveryUiText`, `QaUiText`, `StepCaseGuide`, `StepCorpusSettings`, `StepReviewPlan`, `StepGenerateCorpus`, `StepCaseSummary`). Where none of them answered, the value is marked **[DEFAULT]** and listed under Assumptions. gsd-ui-checker verifies it next.
>
> **Platform:** WinForms desktop (net10.0-windows). All UI is built in code: `InitializeUI()`, a `TableLayoutPanel` root docked `Fill`, a row-index comment on every `RowStyle`, and handlers wired only after every control exists.
>
> **Units:** All pixel values are **logical px at 96 DPI**. Each one goes through `LogicalToDeviceUnits(n)` on the owning control. Font sizes are in **points** and come only from `Theme` factories. New code never calls `new Font(...)` and never uses `Color.*` / `SystemColors`.
>
> **Baseline:** this phase **extends `08-UI-SPEC.md` (approved)** and, through it, the 07/06/05/04/03/02 UI-SPECs. The palette, type scale, spacing tokens, `CardPanel`, banners, state cards, status line, `Plural` helper, tone rules, the confirmation format and DPI & Render Contract rules 1-41 apply unchanged and are not repeated. **Phase 2's `SystemColors`/`Color.Red` values are superseded by `Theme` tokens** (03-UI-SPEC onward); this phase uses `Theme` only. No screen is redesigned. This document covers six small surfaces only.
>
> **Quality bar:** the user runs Windows at 150%. A surface is not done until its 144-DPI render has been inspected by eye against the DPI & Render Contract below.
>
> **Copy rule:** every string below lives in a pure `*UiText` function (unit-tested). Labels showing it set `UseMnemonic = false`. Placeholders: `{n}` is a count formatted with `N0`; `Plural(n, "x", "xs")` is `CaseGuideUiText.Plural`.

## Screen Contracts

### S1. Generate Corpus — GuideChanged card and run refusal (W1)

**Entry decision** (`GenerationUiText.EntryDecision`, pure). New input `GenerationEntryInput.GuideStale` = `CorpusApproval.IsGuideStale(Draft)` computed **before** withdrawal. Order:

```
1. Running                     -> KeepRun
2. HasPlan && GuideStale       -> GuideChangedCard        (new)
3. !HasPlan || !Approved       -> NotApprovedCard
4. ... unchanged (PlanChanged, Unreadable, Ready, dashboards)
```

On `GuideChangedCard`: `CorpusApproval.WithdrawApprovalIfStale(Draft)`, `Revision++`, `await SaveAsync()`, then show the card. The journal is not read. The partial-run banner, dashboards and Ready card are hidden while this card shows (same as every state card).

**Card layout:** the existing centered state card (`CardPanel`, heading `HeadingFont` `Theme.Text`, body `BodyFont` `TextMuted` max width 520, one action button). No new layout.

**Card content** (`GenerationUiText.StateCard(GenerationStateCard.GuideChanged, …, emailsWritten)`):

| Part | Copy |
|------|------|
| Heading | `The case guide changed after this plan was built` |
| Body (no emails written) | `Emails are written from the corpus plan and the guide it was built from, so generation is paused. Open Review Plan to keep this plan and approve it, or re-plan from the current guide.` |
| Body (`n` > 0) | Same text, then ` The {n} emails already written stay in place.` (`n` = 1: ` The 1 email already written stays in place.`) |
| Button | `Review Plan` (**Primary**) |

`n` = `Draft.Corpus.Generation.EmailsWritten` (cached count; the UI thread never replays the journal).

**Action:** `ClickStateActionAsync` gains an explicit `case GenerationStateCard.GuideChanged:` that calls `NavigateToStage(CaseStage.ReviewPlan)` and returns. **It must never fall through to `default:` (`StartOverAsync`).** Test asserts the journal still exists after the click.

**NotApproved card copy** (split by `hasPlan`; Next on this step always passes, so both mention it):

| Case | Heading | Body | Button |
|------|---------|------|--------|
| No plan | `No corpus plan yet` | `Emails are written from an approved corpus plan. Plan and approve it on Review Plan, or click Next to write discovery documents without emails.` | `Review Plan` (Primary) |
| Plan not approved | `Approve the plan first` (unchanged) | `Emails are written from an approved corpus plan. Approve the plan on Review Plan, then come back to this step. Or click Next to write discovery documents without emails.` | `Review Plan` (Primary) |

**`RunCoreAsync` refusal** (defense in depth; replaces the silent `return`; runs before `CreateRunGateway`, so nothing is billed). The status line is set in `Theme.Warning`, and the matching card is shown:

| Condition | Card shown | Status line (Warning) |
|-----------|-----------|------------------------|
| Guide stale | GuideChanged (after withdraw + save) | `Generation did not start: the case guide changed after this plan was built. Open Review Plan to approve the plan.` |
| Not approved | NotApproved | `Generation did not start: the corpus plan is not approved. Open Review Plan to approve it.` |


Initial focus on other surfaces (checker recommendation, locked): S3 NoPlan/Failed/Unreadable cards focus the Primary `Plan Corpus` / `Retry Planning`, never `Skip to Discovery Documents`; S2 PlanDependency banner takes no focus (its Default `Review Plan` button does not grab focus); S4 Corpus Settings keeps focus on the first settings field, and the skip button never takes default focus.
Focal point: the `Review Plan` Primary button (receives focus when the card shows).

### S2. Case Guide — plan dependency notice (W1, SC1 last clause)

**Placement decision (locked):** two parts, consistent with existing patterns.
- **Changed state (after an edit)** uses a new **lowest-priority banner variant** `BannerVariant.PlanDependency` in the existing banner row (row 1). Priority: `StaleCore` > `StaleDownstream` > `NeedsReview` > `PlanDependency`. It reuses the banner exactly (Warning border, white surface, `LabelFont` Warning heading, `BodyFont` TextMuted body, right-side button flow, height from `SizeBanner`).
- **Info state (before an edit)** and the **Changed state while a higher-priority banner holds the row** use a new one-line-or-wrapping **dependency line** in the header, row 2 under the subtitle. This follows the `StepCoreDocument` `_lblGuideNotice` precedent ("The case guide was built from this document. Edits will mark it out of date."), so the user is told about the dependency even when the banner row is taken, and a passive notice never occupies the banner.

**Header layout change** (`headerLayout`, column 0):

```
0: Title                        // AutoSize (unchanged)
1: Subtitle                     // AutoSize (unchanged)
2: Dependency line              // AutoSize (new; collapses when hidden)
```

Dependency line: `Label`, `SmallFont`, `AutoSize = true`, **wraps** (`MaximumSize.Width` = header column 0 width, updated on resize; `AutoEllipsis = false`), `UseMnemonic = false`, `Margin = new Padding(0, 4, 0, 0)`, `Visible = false` when there is no line. `headerButtons` row span becomes 3.

**Decision table** (`CaseGuideUiText.DependencyNotice(bool hasPlan, bool approved, bool guideStale, int emailsWritten)`, pure; returns `Kind` None / Info / Changed plus `Line`, `Heading`, `Body`, `ButtonText`). `guideStale` = `CorpusApproval.IsGuideStale(Draft)` (honors the D-25 kept hash); `emailsWritten` = `Draft.Corpus.Generation?.EmailsWritten ?? 0`.

| # | Condition | Kind | Banner | Dependency line |
|---|-----------|------|--------|-----------------|
| 1 | `hasPlan && guideStale` | Changed | PlanDependency **if no higher-priority variant**, else none | Hidden when the PlanDependency banner shows; Warning-tone line when a higher variant holds the banner |
| 2 | `approved && !guideStale` | Info | none | Muted line |
| 3 | `!approved && !guideStale && emailsWritten > 0` | Info | none | Muted line |
| 4 | anything else | None | none | Hidden |

**Copy:**

| Case | Element | Copy |
|------|---------|------|
| 1 | Banner heading | `The corpus plan was built from an earlier version of this guide.` |
| 1 | Banner body (`n` = 0) | `Generate Corpus will not write emails from this plan until you review it. Open Review Plan to keep the plan and approve it, or re-plan from the current guide.` |
| 1 | Banner body (`n` > 0) | `Generate Corpus will not write emails from this plan until you review it. The {n} emails already written stay in place. Open Review Plan to keep the plan and approve it, or re-plan from the current guide.` (`n` = 1: `The 1 email already written stays in place.`) |
| 1 | Banner button | `Review Plan` (**Default**). Click: `NavigateToStage(CaseStage.ReviewPlan)`. Disabled while the guide is generating |
| 1 | Line (Warning, banner held by a higher variant) | `The corpus plan was built from an earlier version of this guide. Review it on Review Plan before generating emails.` |
| 2 | Line (Muted, `n` = 0) | `The approved corpus plan was built from this guide. Editing the guide withdraws plan approval until you review the plan again.` |
| 2 | Line (Muted, `n` > 0) | `The approved corpus plan and {Plural(n, "generated email", "generated emails")} were built from this guide. Editing the guide withdraws plan approval until you review the plan again.` |
| 3 | Line (Muted) | `{Plural(n, "generated email was", "generated emails were")} written from this guide. Emails already written do not change when you edit it.` |

The banner has no `Not Now`; it disappears when Review Plan's `Keep This Plan` records the kept hash (`IsGuideStale` turns false) or a re-plan rebuilds the plan. Refresh the notice in `RefreshBanner()` and after every save-funnel withdrawal.
